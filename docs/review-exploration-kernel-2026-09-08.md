## 1. Цель документа

Ответить на вопрос владельца: правильно ли выбрано направление (переход от arena-survivor к
exploration/action-roguelite при сохранении текущего combat-ядра), насколько реалистичен переход,
и всё ли учтено для реализации «смены ядра». Документ фиксирует факты, проверенные первым чтением
кода (не только документацией), с точными якорями в ядре и честным списком того, что НЕ было прочитано.

## 3. Ключевые факты о текущей архитектуре (проверено в коде)

- Один файл-ядро `uploads/necro-deluxe.html` + build.py: 49 хирургических патчей по уникальным якорям
  (каждый `assert count==1`), сборка детерминирована (пересобрана 2026-09-08: diff пуст).
- Один rAF-цикл ядра `lr`; игровой step заменяем (`var ur=e=>{sr=e}`) и уже отдан в тесты как `__necro.step`.
- Машина состояний `i` (`menu/play/levelup/pause/spec/p6ui/over/win`): при `levelup|pause|over|win`
  ядро НЕ исполняет игровую логику — только рендер. Это готовый механизм «остановки боя» для модалок.
- Уже существует паттерн mode-гейта: `xr()` (финальный босс) выходит, если `a.mode!=='finale'||…`,
  biome-таймер останавливается при `finaleSpawned`. Т.е. «Exploration через a.mode» — тот же паттерн, что уже в ядре.
- Скейлинг врагов запекается при спавне: `St()` = `hpTime(runMinutes) × (1 + min(powerScale.cap, playerPower×…))`,
  `z()` — аналогично для урона. Фабрика `H(type,x,y)` делает `s.maxhp = round(i.hp*St()*(boss?1:±15%))`.
  Пулы и типы открываются по минутам (`Bt()`: `e>1… e>3.5…`, biome `pool`+`from`).
- XP/уровни: `dt(e)` → `xp+=e*xpMult; while(xp>=need){level++; need=be(level); queue++}`; драфты стартуют из
  `mt()` при `queue>0 && i==='play'`; спека на 5 уровне `gt()`. Тот самый цикл уже патчится build.py.
- Миньоны выбирают цель только среди ЖИВЫХ врагов в радиусе 520 (`Lt(n.x,n.y,520)`), иначе следуют за героем.
- Meta-сохранение: ключ `necro_legion_v1`, defaults `te()`, loader `f(e)` с `schema:1` и числовыми sanitizer'ами;
  версионных миграций нет; при parse error — сброс к defaults.
- **Мета-слой дублируется**: база уже содержит гримуар/дерево (`X`, покупки `vn/yn`, cost 2000–7000 после ×50,
  семейный unlock 80→4000, админ-панель, `modeBtn`), а поверх — extension-слой `nx_progression.js`
  (печати, достижения, доктрины/focus, испытания) и `nx_ext.js` (кузня, HUD ритуалов). Два параллельных
  «владельца» мета-состояния — корень P0 из GAME_REVIEW.
- Тестовая инфраструктура тонкая и рабочая: jsdom + собранный HTML, канвас-стабы, драйв через
  `N.startRun()`/`N.step(1/30)`, оверлеи закрываются как игрок. Сломана только отсутствием `tests/node_modules`
  (`npm i --prefix tests jsdom` чинит; lockfile есть). Cine-тест подтверждает: любой `boss:true` в `G.enemies`
  запускает неймплейт/letterbox/slow-mo из nx-слоя.

## 4. Вердикт (кратко)

| Вопрос | Вердикт |
|---|---|
| Направление: arena → voluntary exploration roguelite | **Да**, верное для дифференциации и тематики некроманта; тонкий срез + gate GO/ITERATE/STOP — правильный инструмент |
| Технология: сохранить minified combat-ядро, оркестрацию наружу | **Да для thin slice** — паттерн mode-гейта уже есть в ядре; страниглер-подход подтверждён практикой |
| Реалистичность плана как написан | **Высокая** — blueprint §29–55 сильный, но 5 швов не специфицированы (см. §6) |
| Смена движка (Phaser 4 и т.п.) сейчас | **Нет** — Phaser 4.2.1 «Giedi» (2026-07-09) остаётся актуальным максимумом; thin slice не требует движка |
| Тестовая база | Восстановима за ~1 шаг; критична, т.к. на ней висят все тикеты #2–#8 |

## 5. Продуктовое направление — детали

### Сильные стороны выбранного направления
- Ядро уже содержит мировые координаты, свободное движение, камеру-фолловер, детерминированный tile-floor
  по `hash(wx,wy)`, полный combat-слой — т.е. «кирпичи» exploration в основном на месте.
- Фантазия некроманта («поднял армию → сам решаешь, что потревожить») работает лучше с добровольным
  исследованием, чем с бесконечным давлением орды.

### Что говорит внешний ресёрч (2026)
- Жанровый канон horde-survivor: авто-аим/авто-атака, спавн орды вокруг игрока, один «уровень», build-crafting
  как главный скилл-чек — почти каждый элемент противоречит «локальным добровольным боям» (DanielZKlein, жанровый анализ).
- Успешные гибриды держат дискретную структуру: Rogue: Genesia (карта = маршрут между аренами), Halls of Torment
  (таймер + порталы), Nordic Ashes (уровневая структура). **Непрерывный открытый мир с полностью добровольными
  локальными encounters + авто-боем массово не доказан** — это и есть ставка thin slice; gate обязателен.
- Дизайн-принципы agency (pre-action luck, decision space, «не давать оптимизировать веселье») поддерживают:
  показывать награду POI до обязательства, одноразовые не-фермерские награды, XP как поддерживающий рост.

### Главные продуктовые риски (названы честно)
1. «Мёртвый воздух» между решениями (density) — ключевая метрика прототипа (§44 GAME_REVIEW: 60–90 с пустоты = плохо).
2. Авто-атака и армия vs «bypass» — см. §6.1: локальность решается структурно, но не полностью.
3. Драфты/модалки на каждый level-up разрушают поток исследования (нужен exploration-кадент XP, §6.2).

## 6. Техническая реалистичность — карта швов (проверенные якоря)

### 6.1. Что уже решено архитектурой и НЕ является проблемой
- «Dormant = дескриптор, не живой враг» (§35.1): враги в ядре всегда идут на игрока (нет idle-врагов),
  поэтому dormant-группы в `a.enemies` попадать не должны. Это не дизайн-вкус, а необходимость.
- Армия и авто-оружие НЕ триггерят dormant-группы: цели выбираются только среди живых записей `a.enemies`
  (миньоны: радиус 520; оружие через `Lt`). Остаточный риск — только при физическом пересечении активного
  боя с соседней зоной (активация по proximity игрока), leash это не покрывает; для thin slice низкая важность.
- Режим «тихо» реализуем паттерном, который уже в ядре (см. `xr`), не изобретением.

### 6.2. Швы, которые НЕ специфицированы в Spec/тикетах/blueprint (главный результат ревью)

| # | Шов | Где именно (якорь, проверен) | Что нужно |
|---|---|---|---|
| S1 | **Скейлинг врагов не принимает spatial danger** | `St()/z()` запекают `hpTime(runMinutes)×power` в КАЖДЫЙ спавн через `H(...)`; пулы по минутам `Bt()`/biome `from` | Спавн-сим, принимающий danger→псевдо-минуты или override; иначе зона Tier-3 на 1-й минуте слабая, и та же зона «мутирует» со временем |
| S2 | **XP/драфт-кадент** | `dt(e)` (цикл уровня, уже патчится build.py), `mt()` по `queue>0 && state==='play'` | «Сильные выборы из POI, kills — только рост» (§42) требует патча/режима XP и драфта; не в списке шагов §50 |
| S3 | **Per-mode scoping extension-систем** | `nx_progression.tick`, `nx_ext` (rAF) работают при `state==='play'`: trials/Chords/Echoes/achievements/knowledge-ash | Определить, что из этого выключено/изменено в exploration, чтобы не загрязнять evidence тонкого среза |
| S4 | **Кинематограф/FX-триггеры** | `nxCine` — nameplate+letterbox+slow-mo на любой `boss:true` (доказано `cine-test.js`) | Boss-POI (вариант B §43) вызовет аренный интро; добавить в director-off список |
| S5 | **Региональный вид пола** | Палитра пола — глобальный `biomeIdx`, вариация per-tile детерминирована `hash(wx,wy)` | Для thin slice ок (один вид); для Milestone-2 регионов нужен per-chunk palette-сим |

Плюс: **manifest швов ядра** (список якорей + инварианты + rebuild-тест) — каждый новый контракт с minified базой
должен быть отслеживаемым, как в build.py (assert уникальности), иначе повторится класс багов ×50/capstone.

### 6.3. Мелкие незакрытые пункты
- Детерминизм мира требует отдельного PRNG (в бою повсюду `Math.random`); `ADR-0004` говорит только о мире — ок.
- Save `schema:1` без миграций; потеря при parse error; bэкап `last_good_save` не делается.
- `trialOv` не переводит `i` — бой идёт под модалкой награды (P0 из GAME_REVIEW, воспроизводится харнессом).
- Win-путь (`Sr`) и 15-минутный finale не должны срабатывать в exploration (покрывается расширением xr-гейта).

## 7. Журнал исправлений собственных выводов (deep pass)

1. **«Армия сломает bypass» — снято.** Миньоны целятся только в живых врагов в 520; dormant не имеет живых записей.
2. **«План тонкий» — неверно; blueprint §29–55** — полноценный пошаговый план с DoD и Product-гейтом.
3. **Новая находка: мета-слой дублируется** между базой (гримуар/дерево/админ) и extension-слоями — архитектурный корень P0 integrity.

## 8. Рекомендуемый порядок действий

1. Восстановить тестовый харнесс (`npm i --prefix tests jsdom`) — на нём висят все тикеты.
2. Дописать Spec #1/тикеты #2/#7 швами S1–S4 (см. §6.2) до начала реализации адаптера.
3. Ввести «kernel seam manifest»: якоря, минимальные замены, acceptance-тесты, rebuild-проверка.
4. Тонкий срез: Exploration mode → гейты director → seed-мир (chunks по `hash(seed,x,y)`) → 1 encounter
   template → Ruins/Altar → danger tiers → navigation MVP → телеграф-доза → human gate #9.
5. До GO/ITERATE/STOP не расширять контент/meta и не трогать движок (Phaser отложен; критерии возврата — в §D ранее).
