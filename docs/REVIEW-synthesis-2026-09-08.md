## 1. Сходимость трёх ревью

Все три независимо пришли к одним вердиктам — расхождений нет:

- **Направление верное** (пивот arena → voluntary exploration; главное доказательство — человеческий гейт #9, а не архитектура).
- **Смену ядра делать через strangler-fig**: сохранить combat-ядро, оркестрацию — наружу через `__necro`. Ревайты движка (Phaser 4.2.1 «Giedi», PixiJS-шаблон «Подземелья Пепла») — осознанно отложены до GO.
- **Для тонкого среза нужно ~2 новых точечных патча ядра** (`spawn` + per-frame симуляционный хук `__nxUpdate`); всё остальное закрывается существующим фасадом (`P6.threatRate/hpTime/dmgTime`, прижатые таймеры, `relics/pacts.push+recalc`, `gfx.floor`).
- **Главный неустранимый риск — продуктовый** (плотность решений / «мёртвый воздух»), правильно вынесен в метрики #8 и human-гейт #9.

## 2. Новые проверенные факты (дельта, отсутствующая в ревью 1–3)

### 2.1. Локальная тестовая среда восстановлена одной командой — расхождение ревью снято
Ревью №1 (pivot) сообщает «smoke 26/26 PASS» (сервер), моё прежнее замечание — «tests/node_modules сломан». Проверено на локальном checkout (Windows, HEAD `3ec6c69`):

```bash
npm i --prefix tests jsdom     # ~одна команда, package-lock.json уже в репо
node tests/smoke-test.js       # SMOKE OK (26/26, 0 ошибок)
node tests/boot-test.js        # ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ (10/10)
```

Вывод: проблема была **только в отсутствии node_modules**, не в harness. Ни smoke, ни boot не требуют `canvas` (он нужен лишь скриншот-инструментам). Рекомендация: (а) добавить в корневой README/`docs/README.md` одну строку про `npm ci --prefix tests`; (б) минимальный CI (GitHub Actions, ubuntu, `npm ci --prefix tests && node tests/smoke-test.js && node tests/boot-test.js && python3 tools/build.py && git diff --exit-code`) закрыл бы и воспроизводимость сборки, и harness — одним workflow. Ничего из этого нет ни в одном ревью.

### 2.2. Правило границы сеединга (уточнение к ADR-0004, отсутствует во всех ревью)
`kernel-review` §6.3 упоминает «отдельный PRNG» одной строкой. Стоит зафиксировать явно как правило для Spec #1:

> **Сеедится только генерация мира** (`hash(runSeed, chunkX, chunkY)` → mulberry32/sfc32 на чанк). **Combat-RNG остаётся `Math.random()`** — разброс урона, дропы, аффиксы в бою сеедить не нужно и вредно: это сломало бы воспроизведение «того же боя по seed» как цель (цель ADR-0004 — воспроизводимость **layout'а мира**, не исходов боёв) и добавило бы bookkeeping в горячий код.

Бонус: в ядре уже есть подходящий integer-hash `ve(x,y)` (микс `374761393`/`668265263`) — PRNG-слоя можно строить по его образцу без новых зависимостей.

### 2.3. Ответ на открытый вопрос ревью №3 (§9B): владелец мета-состояния на время тонкого среза
Kernel-review оставляет это решением владельца. Рекомендация, вытекающая из проверенного кода:

- На v0.1 мета-состояние **замораживается**: `nx_progression.tick` и rAF-логику `nx_ext` глушить в exploration-режиме (это же требуется швом S3 — иначе trials/chords/echoes/achievements/knowledge-ash загрязнят evidence гейта #9).
- Итоговое владение мета-состоянием (базовый гримуар vs extension-слой) — не решать до GO; это вопрос Wayfinder (#10+), и правильным моментом для него является редизайн меты после доказательства loop'а (GAME_REVIEW §20, Этап 3).

### 2.4. Рекомендация по инструменту новых тестов: Playwright, а не расширение jsdom-стаба
Ни одно из трёх ревью не называет инструмент. Текущий harness — jsdom + Proxy-заглушка canvas: он доказал ценность для boot/smoke, но **не умеет рендерить**, а инварианты тонкого среза («маркер нарисован в `gfx.floor`», «visual state POI: undiscovered/active/cleared») — визуальные. Актуальный (2026) стандарт для canvas/webgame e2e — **Playwright**: headless-Chromium, `toHaveScreenshot`, трассировка, CI-friendly. Рекомендация: jsdom-набор оставить как regression для боевого ядра; новые exploration-инварианты (#3–#8) писать на Playwright с того же собранного `necro-v2.html`. Альтернатива «не вводить второй harness» приемлема только если маркер-тесты проверяются спаем (`gfx.floor` подменён шпионом) — но это слабее, чем честный пиксель-снепшот.

### 2.5. Мелкое расхождение нумерации тикетов — исправить
`docs/README.md` пишет «#2 through #8» + «#9», `AGENTS.md` — «#2–#9». По факту в трекере: реализационные тикеты **#2–#8**, human-гейт **#9**. Привести `docs/README.md` к формулировке `AGENTS.md` («implementation chain #2–#8, human gate #9») — косметика, но влияет на «frontier»-логику агентов.
